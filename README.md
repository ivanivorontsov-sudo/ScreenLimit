# Стоп-экран (com.example.screenlimit) — родительский контроль для самого себя

Версия 1.0.0 (versionCode 1) · minSdk 26 · targetSdk 34 · Kotlin, Material 3, без сторонних библиотек кроме AndroidX/Material.

## Что умеет
* **Дневной лимит экранного времени** (часы/минуты), сброс в полночь или в выбранное время.
  Считается время, когда экран включён и разблокирован. **Не считаются**: сам «Стоп-экран» (экран блокировки, подтверждения,
  будильник-предупреждение) и звонки (звонилка по умолчанию, in-call UI). Учёт — по монотонным часам `elapsedRealtime`.
* **Блокировка по расписанию** (например 23:00–07:00), окно может переходить через полночь.
* **Предупреждения-«звонки»**: за 30, 20 и 10 минут до конца лимита — полноэкранный будильник со звуком (поток ALARM) и вибрацией
  поверх экрана блокировки; опционально финальный в момент блокировки. Для лимита пороги считаются по **израсходованному** времени
  (будильник взводится на момент, когда остаток пересечёт порог при непрерывном использовании; если экран гаснет — ждёт).
  Для расписания — по настенным часам (за 30/20/10 мин до начала окна).
* **Режим блокировки**: доступны только звонки (звонилка, входящий вызов, экстренный 112), SMS (приложение по умолчанию), сам «Стоп-экран»,
  системное (экран блокировки, шторка звонков) и **белый список** пользователя (карты, такси, банк — по желанию).
  Всё остальное (рабочий стол, приложения, Настройки, «Недавние») мгновенно возвращает на экран «Телефон на паузе»
  с кнопками «Позвонить», «SMS», «Экстренный вызов 112», «Выйти из блокировки».
* **Выход — ровно 10 подтверждений**: каждый шаг — отдельный экран со своим вопросом, кнопка меняет место (порядок/высота/отступ),
  активируется через 4 с, шаги 3, 6, 8 и 10 требуют ввести фразу (вставка из буфера отключена), шаг «протухает» через 3 мин,
  «Отмена» на любом шаге — обратно в блокировку. После 10/10: **+15 / +30 / +60 минут** или **до конца суток**. Каждый выход — в историю.
* **Защита настроек**: во время блокировки настройки, белый список, экспорт/импорт недоступны. Вне блокировки ужесточение применяется сразу,
  а **любое ослабление** (увеличить лимит, выключить лимит/расписание/строгий режим, сократить окно, расширить белый список, сменить время сброса)
  — только после тех же 10 подтверждений.
* **Строгий режим** — страницы Настроек, через которые можно снять защиту, закрываются всегда, а не только во время блокировки.
* **Статистика**: сегодня за экраном, остаток, прогресс, топ-10 приложений за сутки (UsageStats), история блокировок/выходов/попыток обхода.
* **Экспорт/импорт** настроек и истории в JSON через системный выбор файла (SAF), только вне блокировки.

## Уровни защиты
| | Базовый режим | «Максимальная защита» (владелец устройства) |
|---|---|---|
| Возврат на экран блокировки | AccessibilityService (мгновенно) + overlay + опрос UsageStats | + Lock Task (киоск): «Домой»/«Недавние» не работают, чужие Activity не запускаются |
| Удаление | нужно снять администратора; страницы закрыты во время блокировки | запрещено (`setUninstallBlocked`, `DISALLOW_UNINSTALL_APPS`) |
| Остановить / очистить данные | страница «О приложении» закрыта во время блокировки | кнопок нет (`setUserControlDisabledPackages`) |
| Безопасный режим | нельзя запретить | запрещён (`DISALLOW_SAFE_BOOT`) |
| Сброс, новые пользователи | — | запрещены |
| Смена даты/времени | игнорируется учётом | + запрещена во время блокировки |
| Отладка по USB | — | по желанию запрещается во время блокировки |

## Разрешения и как их выдать
Онбординг показывает статус (✅/⬜) каждого пункта и кнопку «Выдать»:
1. **Доступ к истории использования** — Настройки → Спец. доступ → История использования → «Стоп-экран».
2. **Спец. возможности** — Настройки → Спец. возможности → Скачанные (Установленные) приложения → «Стоп-экран — блокировка» → Вкл.
   **Android 13+ и APK не из магазина**: сначала попробуйте включить (получите «Ограниченная настройка»), затем
   Настройки → Приложения → «Стоп-экран» → ⋮ (справа вверху) → «Разрешить ограниченные настройки» → PIN → снова включите службу.
3. **Администратор устройства** — системный диалог «Активировать».
4. **Поверх других приложений**.
5. **Уведомления** (Android 13+).
6. **Без ограничений батареи** + советы для Xiaomi/Huawei/Honor/Samsung/OPPO (см. онбординг, dontkillmyapp.com).
7. **Точные будильники** (Android 12+/14+).
8. **Полноэкранные уведомления** (Android 14+).

### Максимальная защита (по желанию, нужен компьютер)
1. Удалите аккаунты (Google и др.) — Android не даст назначить владельца, если есть аккаунты; потом их можно вернуть.
2. Включите «Для разработчиков» и «Отладка по USB», подключите телефон.
3. `adb shell dpm set-device-owner com.example.screenlimit/.AdminReceiver`
4. Снять: «Стоп-экран» → Максимальная защита → «Снять максимальную защиту (10 подтверждений)» → `clearDeviceOwnerApp`.
   Удаление приложения: сначала «Снять права администратора (10 подтверждений)».

## Обновления и данные
Правило для всех будущих версий: **обновление никогда не стирает данные пользователя**.
* Всё хранится в одном файле SharedPreferences **`sl_store`** с неизменными ключами:
  `sl_schema`, `sl_settings`, `sl_state`, `sl_history`, `sl_installed_at`, `sl_onboarding_done`, `sl_owner_protection`,
  `sl_block_adb_during_lock`, `sl_pending_settings` (+ отладочные `sl_debug_*`, читаются только в debug).
  **Ключи и имя файла нельзя переименовывать или удалять.**
* Значения — JSON; поля только **добавляются** с дефолтами (`optInt/optBoolean(..., default)`), неизвестные поля игнорируются →
  старые данные и старые экспорты читаются новыми версиями, и наоборот.
* Миграции — только аддитивные, по `sl_schema` (`if (v < N) { добавить ключи }`), ничего не удаляют.
* Значения по умолчанию («сиды») записываются **только если ключа ещё нет**.
* Импорт JSON ничего не удаляет: история **объединяется** (без дублей), настройки применяются по правилам ослабления.
* Подпись — всегда один и тот же ключ (`/home/box/.android/debug.keystore`), иначе обновление поверх невозможно.
* `versionCode` только растёт. Проверено: `adb install -r` поверх установленной версии сохраняет настройки, историю и состояние блокировки.
* `allowBackup=false` — чтобы восстановление облачной копии не «снимало» блокировку; для переноса используйте экспорт JSON.

## Тестирование (debug-сборка)
Отладочный приёмник есть **только в debug** (`src/debug`), в release-APK отсутствует:
```
adb shell am broadcast -n com.example.screenlimit/.DebugReceiver --el warn_unit_ms 3000 --el limit_ms 120000 --ez reset_usage true
# пороги 30/20/10 «минут» становятся 90/60/30 секундами, лимит — 2 минуты
adb shell am broadcast -n com.example.screenlimit/.DebugReceiver --ez clear_debug true
```
Скрипты: `tools/ui.py` (дамп/тапы/скриншоты), `tools/exit_flow.py` (прохождение 10 подтверждений).

## Известные ограничения
* Базовый режим: безопасный режим и сброс к заводским не запретить; если пользователь успеет отключить спец. возможности вне блокировки —
  возврат на экран блокировки работает с задержкой (опрос UsageStats раз в 5 с + onUserLeaveHint).
* Режим владельца: сброс из recovery (кнопками) остаётся возможен; назначение владельца требует устройства без аккаунтов.
* Входящий звонок в киоске: пакеты in-call UI у разных производителей различаются — добавлен список для AOSP/Google/Samsung/Xiaomi/Huawei.
